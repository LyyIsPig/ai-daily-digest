## 研究精选

### 1. StreamDuo：让实时解说 Agent 按需询问研究 Agent

**一句话解释：** 面对没见过的游戏，解说模型在需要知识时向另一个 Agent 查询游戏 Wiki，同时继续处理直播流。

**比喻讲解：** 想象一位解说员临时接手一场陌生游戏的比赛：他熟悉解说节奏，却不认识场上的角色和道具。后台助手负责翻资料，解说员只在资料能帮助自己讲清楚时发问，再把查到的内容融入解说。StreamDuo 研究的就是这两位“搭档”何时配合，以及怎样用好可能不够准确的回答。

**核心方法：** 系统将可训练的解说器与冻结的研究 Agent 配对，用信息增益标签学习何时提问，再用自蒸馏学习使用含噪的回答。研究 Agent 的检索结果约两秒后返回。

**关键证据：** 摘要报告，在《博德之门 3》上训练、十款未见游戏上测试，相比使用相同数据训练的 Proact-VL，实体召回由 0.082 提升到 0.116，源游戏知识泄漏由 9.9% 降至 1.0%。结果适用于论文所设定的跨游戏解说评测。

**学习启发：** 做 RAG / Agent 项目时，可以单独设计“是否值得检索”的决策，以及检索期间主流程如何继续运行。这是根据方法作出的工程建议。

来源：[论文页面](https://huggingface.co/papers/2611.01120)；[作者提供的代码链接](https://github.com/ZixianGao/StreamDuo-code)

### 2. FrontierPhysics：评测 Agent 的完整科研流程

**一句话解释：** 用接近科研流程的任务，观察 Agent 能否从查文献一直做到研究结果与稿件产出。

**比喻讲解：** 把 Agent 看作一位待考核的科研助理，考题是一项完整的研究任务：先找相关工作，再设计方案、开展实验，最后交出有证据支持的报告。评委既检查计算和实验是否正确，也按专家制定的标准评判研究质量，借此观察它能否把各个步骤连成可靠的工作流程。

**核心方法：** 42 位物理学家构建 56 个任务，覆盖九个领域；结合确定性验证器和专家评分标准，检查正确性与研究质量。

**关键证据：** 摘要报告测试了 22 个模型、26 种配置，每种配置的 168 次 rollout 中，通过次数均未超过 46 次。这个口径是各配置的运行次数，不能直接写成“56 项任务里完成了 46 项”。

**学习启发：** 为自己的 Agent 设计评测时，可以同时检查过程产物：引用是否支持结论、计划是否可执行、实验是否对应问题、最终答案是否经过验证。

来源：[论文页面](https://huggingface.co/papers/2611.06910)。

### 3. PyRUA-DataFarm：用编程 Agent 生成机器人训练数据

**一句话解释：** 编程 Agent 在仿真中重建任务，生成带动作标注的数据，减少逐条人工遥操作采集的需求。

**比喻讲解：** 教机器人完成一项操作，通常需要人反复示范。DataFarm 像一间虚拟教学录像工厂：先参考一次真实示范搭好练习场，再编排动作、拍出多个视角的录像，并给画面配上对应的动作说明。独立的“质检员”审核合格后，这些教材才进入训练集。

**核心方法：** 输入数据需求和一次真实场景标定示范，由 Agent 编写场景、专家控制器和成功判定器；仿真提供动作，视频模型生成多视角画面，独立判定环节审核数据。

**关键证据：** 在论文的五项真实机器人任务设置中，摘要报告使用生成数据训练的策略与遥操作数据训练策略，在 100 次试验中分别成功 93 次和 84 次。该结果需要结合正文的数据规模与任务设置理解。

**学习启发：** 可以借鉴“生成—独立审核—入库”的数据流水线，尤其是让审核器独立于数据生成器。机器人部署本身还需要仿真、视频生成和真实硬件条件。

来源：[论文页面](https://huggingface.co/papers/2611.05320)；[提交者提供的代码分支](https://github.com/DAGroup-PKU/PyRUA-Lean/tree/DataFarm)。

## 开源项目精选

### 4. NVIDIA/auto-ontology：为数据分析 Agent 提供业务语义

**用途：** 从企业元数据建立语义和图结构，解释指标、实体、关系与数据来源，供 Agent 检索上下文和查询数据库。

**比喻讲解：** Agent 刚接触一家公司的数据库，就像新员工面对满柜子用缩写标记的文件：即使找得到文件，也未必知道“收入”在不同部门按什么口径计算。Auto Ontology 像一位资料管理员，把术语含义、业务关系和资料出处整理成词典与地图，帮助 Agent 理解该查什么、去哪里查。

**值得关注的功能：** README 描述了元数据发现、业务定义对齐、查询校验与来源追踪，并提供 MCP、CLI 和 API 接口。

**使用门槛：** 项目包含数据库、后端和前端等组件。官方快速开始需要 Docker Compose、uv 和 NVIDIA API Key，许可证为 Apache-2.0。

**建议：** 对 RAG、知识图谱或 Text-to-SQL 感兴趣时，优先读它如何组织业务定义和数据来源；直接部署前先确认模型服务与运行资源。

来源：[官方仓库](https://github.com/NVIDIA/auto-ontology)。

### 5. max-sixty/worktrunk：管理多个编程 Agent 的 Git worktree

**用途：** 简化 worktree 的创建、切换、列表和清理，让不同任务拥有各自的工作目录。

**比喻讲解：** 几位程序员同时修同一份工程，如果挤在一张工作台上，很容易动到彼此正在修改的材料。Git worktree 提供各自独立的工作台，Worktrunk 则像管理员，帮忙分配、切换、查看和收拾这些工作台。任务完成后，成果仍要经过检查再合并。

**值得关注的功能：** 在基础目录管理之外，提供 hooks、合并辅助和状态查看等功能。它能帮助隔离工作目录；多个任务最终合并时仍需要检查代码之间的冲突。

**使用门槛：** 需要理解 Git 分支和 worktree。README 提供 Windows 安装方式，并提醒其命令名与 Windows Terminal 的 `wt` 可能冲突，可使用 `git-wt`。

**建议：** 适合经常同时修改多个功能的工作流。可以先用一个练习仓库体验两个 worktree，再决定是否用于日常项目。

来源：[官方仓库](https://github.com/max-sixty/worktrunk)。
