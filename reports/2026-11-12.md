## 研究精选

### 1. RoboScript：让机器人在上下文里排练技能

**一句话解释：** World In-Context Learning 让冻结模型从一次示范开始，在模拟器里试错并把有效经验写进上下文任务记忆，而非更新网络权重。

**比喻讲解：** 新员工看过一次演示后，先在训练场完成多次彩排，把有效步骤整理成操作卡；到新工作台时，他带着卡片执行。模拟反馈对应彩排记录，Task Memory 对应可迁移的操作卡。

**核心方法：** RoboScript 将任务在仿真中排练，提取语义化步骤与对象角色，冻结为任务记忆后部署到新场景，并限制部署输入为真实机器人可得的信息。

**关键证据：** 作者在 RoboTwin 2.0 的 50 项任务上报告，单示范、无梯度更新下平均成功率为 83.4%，比最强已训练策略高逾 20 个百分点；该结果来自其清洁与随机化设置。

**学习启发：** 对具身 Agent，可先将“在仿真中被验证的操作过程”作为可审阅记忆，再评估跨场景迁移，而不只比较模型微调前后。

来源：[论文页面](https://huggingface.co/papers/2611.12885)；[官方代码](https://github.com/ArcheOne-AI/RoboScript)。

### 2. WikiTrace：让 Agent 在行动前核查记忆来历

**一句话解释：** WikiTrace 将简短经验、轨迹成败原因和原始轨迹链接起来，减少错误或误用的记忆导致的退化。

**比喻讲解：** 一句“上次这样做成功了”的心得很像缺失上下文的传言。系统允许 Agent 顺着链接翻到原始工单，确认当时条件和失败原因后再决定是否照做。

**核心方法：** 当经验缺细节、彼此冲突或来自失败轨迹时，Agent 用终端工具下钻原始证据，补全或修正经验后再行动。

**关键证据：** 作者在五个 Agent 基准上报告其优于现有记忆方法；相对只提供相同 insights 的基线，平均高 3.2 分。结果适用于论文的记忆编译和检索设定。

**学习启发：** 记忆库至少应记录适用条件、来源轨迹和可回查链接；“可检索”不等于“可直接信任”。

来源：[论文页面](https://huggingface.co/papers/2611.14320)；[官方代码](https://github.com/yukyeongleee/wikitrace)。

### 3. MMDM：在大选项空间里评测结构化决策

**一句话解释：** MMDM 用长上下文、复杂依赖和最多 1,024 个选项测试一次前向决策模型的选择能力。

**比喻讲解：** 普通选择题像从四个答案中选一个；这里更像采购员在一千个条目中同时满足预算、依赖和组合限制。答对常识并不保证能选对整套方案。

**核心方法：** 基准含 5,448 题、16 类任务，覆盖 Agent 状态追踪、工具与技能选择、偏好判断和量规评分，支持单选、多选与软标签决策。

**关键证据：** 作者评测 28 个模型；示例中 Perplexity Decider-V1.2 的世界知识单选准确率为 78.75%，在选项逻辑和约束规划降至 53.95% 与 47.95%，全模型最佳多选准确率为 36.81%。

**学习启发：** 评估路由或工具选择模型时，应把互相依赖的选项、多选完整性和约束违反单独计分。

来源：[论文页面](https://huggingface.co/papers/2611.14309)；[项目页面](https://mmdm-benchmark.github.io/)。

### 4. FINCOSMOS：不把金融 Agent 放进“标准答案”温室

**一句话解释：** FINCOSMOS 模拟信息不完整的用户和开放网络数据，让 Agent 在时间截点前自行澄清策略、回测并提交可复算交付物。

**比喻讲解：** 客户只说“想做稳健投资”，分析师必须追问约束、找历史数据、避免偷看未来，然后交出能被审计员逐项复算的报告。用户满意并不代表报告正确。

**核心方法：** 隐藏策略按组合语法生成；程序检查策略一致性、数据时点和每个指标，15 项否决检查均通过且用户满意才接受。

**关键证据：** 作者在 150 次会话中报告，没有一次被完整接受；即使模拟用户签收的 35 次也全部未通过程序检查。该发现说明此基准中表面满意与可验证正确性存在差距。

**学习启发：** 高风险 Agent 的验收应直接校验数据来源、时间边界和可复算产物，而非只使用 LLM 评审或用户主观满意度。

来源：[论文页面](https://huggingface.co/papers/2611.07464)。

### 5. BioAgent-DF：同时审计科学 Agent 的结论和证据链

**一句话解释：** BioAgent-DF 通过在原计算位置恢复或替换工具状态，检查科学 Agent 的判断、读取内容和引用是否同步变化。

**比喻讲解：** 复核实验报告时，不能只看最终写了“通过”还是“不通过”，也要看依据哪组测量数据得出结论。工具状态像仪器读数，Agent 的可见历史则是已被这些读数影响过的笔记。

**核心方法：** 在同一科学计算点配对保存参考值与候选值，重放、恢复或移植后运行 Agent，并比较判决、读取和引用的变化。

**关键证据：** 作者在 hERG 心脏安全筛选中报告，恢复 Agent 读到错误值之前的执行状态并提供认证分数，找回 39 项改变的决策；仅替换预测文件没有恢复任何一项。这是特定故障重放设置下的结果。

**学习启发：** 对科学工具 Agent，应保存可恢复的状态快照与数据血缘；修正源文件不一定能撤销已经形成的错误决策。

来源：[论文页面](https://huggingface.co/papers/2611.01527)；[项目页面](https://intosyn.github.io/BioAgent-DF/)。

### 6. LEASH：为机器人 Agent 增设三道安全关

**一句话解释：** LEASH 在任务接收、每项动作和不可逆提交前，以共享安全策略复核机器人计划。

**比喻讲解：** 机器人端着水经过电脑时，安全不该只在接到指令时问一次“能不能做”；它还要在出发、经过危险区域和松手倒水前分别确认。三道门对应任务、动作和提交 gates。

**核心方法：** RoboRisk 覆盖任务拒绝、计划修复、执行期危险、注入和序列记忆五类风险；LEASH 用决策模型结合 RGB-D 观察，对规划器输出进行分层把关。

**关键证据：** 作者在 92 个模拟和 13 个实体机器人任务上评测，并报告 LEASH 降低六个基础模型的伤害行为、基本保持任务完成率；四个规划器在 13 次实体试验中未观察到伤害。需结合其风险定义理解。

**学习启发：** 具身安全需要将不可逆操作显式定义为提交点，并把当前环境状态纳入复核，而非只做一次提示词级过滤。

来源：[论文页面](https://huggingface.co/papers/2611.14115)；[官方代码](https://github.com/zhuqinfeng1999/LEASH)。
