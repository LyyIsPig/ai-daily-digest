## 研究精选

### 1. Harness-S：用兄弟 Harness 救援失败轨迹

**一句话解释：** Harness-S 通过专门化的兄弟执行 harness 替换基础 harness 的失败强化学习轨迹，并把获得的能力迁移回原始执行系统下的单一策略。

**比喻讲解：** 不同工作流脚手架像不同工种：有的擅长查资料，有的擅长测试。系统先让主力工种尝试；全部失败时才叫来最合适的同事处理同一任务，再将成功做法用于训练主力，最终仍让主力在原工作台上完成任务。

**核心方法：** 作者构建固定的 Sibling Harness Pool；仅在基础 harness 的初始尝试均失败时触发救援。自适应路由器依据行为画像和多个 LLM 的投票选择 Top-k 兄弟 harness，并随策略训练更新画像锚点。

**关键证据：** 摘要称在 AppWorld、SWE-Gym、DBBench 上，训练后的策略回到原始基础 harness 时优于仅做策略训练；作者页面的讨论举例，Qwen3.5-9B 在 AppWorld 的 Pass@3 从 64.89 升至 72.52。该数字和迁移结论均为作者报告，依具体预算和设置而定。

**学习启发：** 设计 Agent 训练时，可将多种脚手架作为“困难样本生成器”，但应单独验证能力是否真的迁移回统一、较简的部署 harness。

来源：[论文页面](https://huggingface.co/papers/2611.04277)；[官方代码](https://github.com/zhangkangning/Harness-S)。

### 2. EvoMemState：把长期记忆视为状态而非事实清单

**一句话解释：** EvoMemState 为个人 Agent 同时维护持久事实、事实间的关系状态与面向当前请求的推理状态。

**比喻讲解：** 普通记忆库像装满便签的盒子，容易忘记哪张已经失效或与别的便签冲突。它额外维护一本“关系账本”说明事实的有效性、范围和变化，再为当前问题写一张“本次使用指南”。

**核心方法：** 本体引导模块提取持久事实并构建关系状态；基于 RL 的状态演化策略生成请求特定的推理状态；最终将相关事实、关系状态和推理状态一起送入回答过程。

**关键证据：** 作者摘要称，在长期对话与记忆使用基准中相对现有记忆系统提升检索完整性和基于记忆的回答准确性；页面讨论给出 MemSyco-Bench 上 Qwen3-8B 的 57.6% 准确率示例。该数值来自页面讨论，正式比较应以论文实验表格为准。

**学习启发：** 做个人化记忆时，不应只去重事实；也应显式记录时效、冲突、适用范围与当前任务的使用优先级。

来源：[论文页面](https://huggingface.co/papers/2611.03743)；[官方代码](https://github.com/XMUDeepLIT/EvoMemState)。

### 3. VisSearch-Bench：长程视觉搜索仍是多模态 Agent 的难题

**一句话解释：** VisSearch-Bench 用需要持续管理视觉上下文的任务，评估多模态 Agent 如何把图像证据与外部检索结合起来。

**比喻讲解：** 普通图文搜索只需看照片认出一个地标再查名字；这里更像解谜：要比较多个候选物的外观、局部和空间关系，在多轮搜索中保留证据链，最后交出能逐项核验的答案。

**核心方法：** 基准含 204 个人工撰写任务，覆盖集合式、序列式、宽深混合、竞争性消歧和视觉结构引导五类搜索，提供参考答案、可追溯证据与评分规则；同时计完整任务成功率和过程分数。

**关键证据：** 作者报告对 16 个多模态模型的评测中，最佳系统完整解决率为 26.47%，即便它们可使用搜索工具。该结果揭示视觉证据与检索结果连接的困难，而非对所有视觉 Agent 的通用能力判定。

**学习启发：** 评测视觉 Agent 时，除最终答案外可检查中间子问题、图像证据保留和跨轮引用是否完整。

来源：[论文页面](https://huggingface.co/papers/2611.04894)；[项目页面](https://dingwu1021.github.io/VisSearch-Bench/)；[官方代码](https://github.com/AntGroup/VisSearch-Bench)。

## 开源项目精选

### 4. google/skills：Google 产品与技术的 Agent Skills 集合

**用途：** 汇集面向 Google 产品、技术及 Google Cloud 的 Agent Skills，供 Agent 工作流按需安装和配置。

**比喻讲解：** 把通用 Agent 比作一位新员工，仓库提供按产品分类的操作手册；你不必让他背下所有手册，只选当前项目需要的那一册放进工具箱。

**值得关注的功能：** 官方 README 提供通过 `npx skills add google/skills` 选择具体技能或全部技能的入口，并支持按项目或全局范围配置；目录同时包含云端插件与技能集合。

**使用门槛：** 需要 Node.js / npx；安装前应审阅所选 skill 的范围、外部服务权限与更新行为。仓库使用 Apache-2.0 许可证。

**建议：** 对 Google Cloud 或 Google 产品集成有明确需求时，优先挑选单个最小技能集，避免为不相关能力扩大权限与上下文。

来源：[官方仓库](https://github.com/google/skills)。

### 5. cloudflare/security-audit-skill：可独立复核的代码安全审计

**用途：** 将 coding Agent 组织为多阶段安全审计流程，输出经独立核验、机器可读的发现。

**比喻讲解：** 安全审计不是让一位检查员从头看到尾：先有人画出建筑和入口，再按区域分派检查，随后换一位不参与原检查的人专门尝试推翻每个可疑结论。

**值得关注的功能：** 官方说明包含侦察、覆盖驱动 hunting、候选验证、结构化输出、独立记录核验与中立报告；README 将其描述为 Cloudflare 漏洞发现 harness 的单仓库起点。

**使用门槛：** 需要将审计目标、信任边界和授权范围界定清楚；自动化发现必须经过独立验证，不能将候选报告直接等同于漏洞。许可证为 MIT。

**建议：** 适合在已获授权的代码库中，先用它建立覆盖账本和验证关卡；对生产系统仍应结合人工安全审查与负责披露流程。

来源：[官方仓库](https://github.com/cloudflare/security-audit-skill)。
