## 研究精选

### 1. OS-Omni：考查跨设备的长流程操作

**一句话解释：** OS-Omni 用跨平台环境评测电脑操作 Agent 能否完成涉及持续应用状态的复杂工作。

**比喻讲解：** 助理要先在电脑整理日程，再用手机完成后续步骤；中途产生的账户、购物车或日历状态都必须保留下来，最后才算完成。

**核心方法：** 基准覆盖 Windows、Ubuntu、macOS、iOS、Android 和 Web；首版每个平台 48 项任务，另有 12 项连接桌面和 Android 手机的流程，并提供最终状态的可执行检查器。

**关键证据：** 作者报告，首版中最强被测 Agent Claude Opus 5.5 平均成功率为 68.5%，人工参照为 77.3%；不同平台差距不均，iOS 和 macOS 差距超过 25 个百分点。

**学习启发：** 电脑操作评测应检查跨平台的最终状态，并拆开各平台结果观察可靠性。

来源：[论文页面](https://huggingface.co/papers/2611.34232)。

### 2. DRBench Pro：研究报告覆盖了多少知识

**一句话解释：** DRBench Pro 用结构化知识关系衡量深度研究 Agent 报告的广度和深度。

**比喻讲解：** 评价旅行指南时，一方面看是否覆盖多个城市，另一方面看每个城市的交通、住宿等问题是否讲透；只把城市列全不等于研究充分。

**核心方法：** 从维基百科构建局部知识树，抽取子图生成问题和有证据依据的评分条目，分别衡量主要方向的广度和知识链的深度。

**关键证据：** 作者报告基准含 24 个领域、144 个案例和 44102 条评分项；16 个被评测 Agent 中最好者的综合覆盖率为 57.04%，结果依该知识树与评分规则。

**学习启发：** 对深度研究系统，除了语言质量，也可检查关键主题是否遗漏以及各方向是否有足够证据。

来源：[论文页面](https://huggingface.co/papers/2611.34852)。

### 3. LLM 上下文工程：从失败经验中总结并不总有效

**一句话解释：** 研究比较让模型根据试验结果自动生成指令或经验的多种上下文工程方法。

**比喻讲解：** 学生整理错题时，如果错误原因各不相同，一条笼统的口诀可能只适用于其中一部分，甚至掩盖具体问题。

**核心方法：** 作者构建具有不同推理模式的数据集，对多个 8B 模型家族比较上下文工程方法与简单基线，并分析失败轨迹的多样性。

**关键证据：** 摘要报告没有一种方法在所有任务中胜出；跨数据集和模型，方法收益与失败模式多样性呈负相关，相关系数为 −0.5，p≤0.05。相关性不能单独证明因果。

**学习启发：** 把失败压缩成通用经验前，可以先分类检查失败原因，并保留具体反例进行验证。

来源：[论文页面](https://huggingface.co/papers/2611.30494)。

### 4. 数据库中的 Agent 错误：损害与恢复取决于什么

**一句话解释：** 论文研究 Agent 在不同数据库系统和权限条件下出错时，实际损害及可恢复性如何变化。

**比喻讲解：** 两个车间都可能有人误删材料，但门禁限制、备份是否可触及以及能否恢复，会改变最终损失。

**核心方法：** 作者使用包含多种危险情况的数据库任务，在九种核心引擎上评测多个小型开源模型驱动的工具调用 Agent，并区分预注册结果与事后分析。

**关键证据：** 摘要报告核心实验共 9468 次试验；作者指出不同引擎在可撤销操作方面差异明显，并明确部分事后分析是探索性的，不能当作预注册结论。

**学习启发：** 部署数据库 Agent 时，应把权限范围、备份保护和恢复演练作为独立设计问题。

来源：[论文页面](https://huggingface.co/papers/2611.30483)。

## 开源项目精选

### 5. cathrynlavery/diagram-design：用 Agent 制作可编辑图表

**用途：** 该 Agent 技能根据自然语言生成自包含的 HTML 与 SVG 图表。

**比喻讲解：** 绘图助理拿到一套布局模板和品牌样式说明后，选择适合的图形并绘制；交付的是可以继续查看和修改的图稿。

**值得关注的功能：** README 描述了多种图表类型、品牌样式适配及 PNG、SVG 导出；它可在支持 Agent Skills 的多个工具中使用。

**使用门槛：** 需要兼容 Agent Skills 的宿主；项目标明 MIT 许可证。本次仅核对官方说明，未实际运行。

**建议：** 适合先用非敏感示例验证图表表达和导出效果，再决定是否接入团队工作流。

来源：[官方仓库](https://github.com/cathrynlavery/diagram-design)。
