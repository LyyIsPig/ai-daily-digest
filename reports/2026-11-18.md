## 研究精选

### 1. SPILLWAY：为工具调用目的地建立检查底线

**一句话解释：** SPILLWAY 通过检查工具返回中目的地的来源，降低提示注入诱导 Agent 将操作重定向给攻击者的风险。

**比喻讲解：** 助理收到一份文件后准备付款，付款对象如果只出现在文件正文的一张便条里，就需要停下来；若来自只读工具返回的结构化字段或固定授权规则，才进入相应检查流程。被移除的可疑文字保留作证据。

**核心方法：** 确定性的准入检查区分用户任务、只读工具的类型化返回和固定委派规则；清理器处理匹配到的指令样式文本，本地判断器可恢复部分被拒调用，但不能恢复目标位于已移除文本中的调用。

**关键证据：** 作者报告，在三种模型骨干及其中一种模型的七套任务测试中，标准模板化注入未能将动作重定向到攻击者目标；结果限于论文所测攻击和防御设置，并非通用安全保证。

**学习启发：** 在工具 Agent 中，可以将目的地授权与自然语言内容清理分开，保留可追溯的拒绝依据。

来源：[论文页面](https://huggingface.co/papers/2611.07222)。

### 2. SWE-CoWork：从澄清需求到交付的团队实战

**一句话解释：** SWE-CoWork 模拟软件组织中的协作，评测编程 Agent 能否找齐分散需求、实现代码并完成交付。

**比喻讲解：** 新员工只收到简短交接，需要向产品、开发和其他同事分别询问，再对照记录处理矛盾信息。最终验收不仅看改了多少代码，还看整项任务是否完成。

**核心方法：** 基准包含 101 个真实仓库中的 101 项任务、11 种语言和 12 个应用领域；模拟 26 位职责和知识范围不同的同事，使用私有可执行测试验收。

**关键证据：** 作者评测 11 个模型，报告两项领先配置通过约 63% 的 fail-to-pass 测试，但完整完成的任务不足 8%。完整需求预先提供可提高部分测试通过率，却未改善完整任务成功率。

**学习启发：** 应持续跟踪需求、实现、验证和交接的对应关系，避免将部分测试通过等同于任务完成。

来源：[论文页面](https://huggingface.co/papers/2611.20218)。

### 3. Termination Lag：补丁正确之后还发生了什么

**一句话解释：** 研究逐个测试编码 Agent 执行过程中生成的补丁，测量第一次正确解出现后到运行结束之间的步骤。

**比喻讲解：** 维修工可能很早就修好了机器，但还要检查和查看其他部件；这些步骤有助于验证，却也可能再次改坏已修好的部分。关键是区分必要验证和无效的继续修改。

**核心方法：** 在五个模型、两个 Agent 框架和三个 SWE-bench 数据集上记录并测试每个不同的代码补丁。

**关键证据：** 作者报告，38%–82% 最终成功的运行在第一次源码编辑时就出现正确解；1%–8% 的情况中，后续活动破坏了先前正确补丁，使最终结果错误。

**学习启发：** 可在评测中记录首次正确解、后续验证和最终回归，而不是只看结束时的结果；验证仍然必要。

来源：[论文页面](https://huggingface.co/papers/2611.14960)。

### 4. Accelerate Bench：优化完整程序，而不只是微基准

**一句话解释：** Accelerate Bench 让编程 Agent 在固定工作负载和正确性约束下，决定如何优化完整 CPU 应用。

**比喻讲解：** 工程师改造生产线时，单台设备加速未必让整条线更快；机器配置、工序搭配和最终产出是否正确都要一起检查。

**核心方法：** 32 个任务来自科学应用和超算竞赛，提供工作程序、工作负载、计时边界及允许修改范围；公开测试支持迭代，独立验证器评价最终结果。

**关键证据：** 作者在 1.1 版基准上评测 16 个模型与 harness 组合，Score@1 为 25.5%–67.4%；两项领先配置在至少 22 个任务上达到两倍或以上加速。

**学习启发：** 性能 Agent 应同时记录正确性、构建与运行配置，以及跨文件优化之间的相互作用。

来源：[论文页面](https://huggingface.co/papers/2611.20882)；[项目页面](https://acceleratebench.com/)。

## 开源项目精选

### 5. microsoft/aspire-skills：为分布式应用开发提供专门技能

**用途：** Aspire Skills 为处理 Aspire 分布式应用的编程 Agent 提供技能包、插件及扩展。

**比喻讲解：** 新工程师面对复杂设备时，不必靠一份笼统说明书处理所有事情；初始化、部署、监控各有专门手册，入口负责将问题分发给合适的手册。

**值得关注的功能：** README 列出项目初始化、应用编排、部署、监控和终端等技能，并提供诊断与 AppHost 相关扩展。

**使用门槛：** 需要支持相关技能或插件的 Agent 环境，并了解 Aspire 项目和对应 CLI；MCP 配置是独立的可选步骤。实际安装方式取决于宿主与版本。

**建议：** 如果正在开发 Aspire 应用，可以先阅读监控和编排技能的边界，再选择最需要的能力。

来源：[官方仓库](https://github.com/microsoft/aspire-skills)。
