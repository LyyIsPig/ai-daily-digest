## 研究精选

### 1. Sage-Taiyi：让科研 Agent 反思下一步研究什么

**一句话解释：** Sage-Taiyi 将科学理解、证据与未解问题显式整理出来，用它们决定下一项研究目标和推理方法。

**比喻讲解：** 研究组长会把已验证的结果、仍有争议的假设和没回答的问题写进讨论板，再据此安排实验。系统中的监控相当于更新这块讨论板，控制环节则负责调整下一步要查什么、怎么查。

**核心方法：** 以元认知架构持续修订对证据、假设和问题的理解，并从可复用的推理方法中选择适合当前目标的方法。

**关键证据：** 作者在含 265 个任务、覆盖十个学科的 Taiyi-Bench 上报告，八项指标均列第一；总体分数为 54.0，对照 AI Scientist-v2 为 47.9。另有五项专家参与的验证协作，结论仍应结合相应实验条件理解。

**学习启发：** 科研或调研 Agent 可把“已证实、待证实、下一步问题”分开保存，避免只累计资料而不更新研究方向。

来源：[论文页面](https://huggingface.co/papers/2611.12762)；[项目页面](https://alpha-innovator.github.io/)。

### 2. Reframe：让视觉 Agent 对齐工具观察而非只对齐答案

**一句话解释：** Reframe 训练视觉 Agent 通过工具取得并使用证据，再把不合格的中间工具动作修复为可用观察。

**比喻讲解：** 侦探拿到放大后的照片后，必须基于新细节继续调查；如果他取证方式有误，督导会先把这一步纠正，再让调查从可靠证据继续。工具返回内容就是照片细节，修复后的动作让后续学习不建立在坏证据上。

**核心方法：** 第一阶段以证据感知奖励和随机移除原始视觉输入，促使模型依赖工具观察；第二阶段在 rollout 中替换不足的工具动作，并从修复后的观察继续多教师蒸馏。

**关键证据：** 作者在 14 个图像与视频基准上报告优于 Mix-RL 与常规 MOPD；消融实验显示其方法提高了对工具观察的依赖与工具增益。该结论来自作者设定的训练与评测范围。

**学习启发：** 视觉工具 Agent 的评测不应只看最终答对率，也应记录是否获取了足够证据、是否真正使用了工具返回。

来源：[论文页面](https://huggingface.co/papers/2611.12886)。

### 3. Longtail-SWE：让编码 Agent 评测覆盖更多语言生态

**一句话解释：** Longtail-SWE 将真实 issue 修复整理为可执行任务，覆盖 Clojure、Dart、Elixir、Haskell、Kotlin、Swift 等 13 种语言。

**比喻讲解：** 出卷人先让考生做一道真实修复题，再让阅卷员检查题目描述和测试有没有误伤合理答案；发现问题就修题后再入题库。求解器、评审器和修复器对应这三种角色。

**核心方法：** 在候选任务构建中引入 solver—judge—repairer 流程，结合求解轨迹和测试结果修订题目描述与测试，保留可执行且有挑战的工程问题。

**关键证据：** 作者发布 202 个任务及其环境、构建与评测工具和轨迹；实验评估九种模型配置的成功表现、一致性与资源使用。论文页未将这些任务简化为单一通用分数。

**学习启发：** 构建代码 Agent 基准时，测试应既防止错解通过，也避免拒绝符合需求的不同实现。

来源：[论文页面](https://huggingface.co/papers/2611.10304)；[项目页面](https://longtail-swe.com/)。

### 4. AutoVend：在长期经营约束下检验 Agent

**一句话解释：** AutoVend 让一个 Agent 在 180 个模拟日内运营 20 台售货机，观察连续决策能否产生实际经营回报。

**比喻讲解：** 店长不能只看今天卖得好不好，还要平衡仓库、到货时间、过期损耗、补货费用与不同地点的需求。每一天的选择都会改变之后还能卖什么、还剩多少现金。

**核心方法：** 数据驱动的模拟器将共享仓库、采购提前期、付费补货、商品过期和日常成本纳入网页操作界面，并分析跨点位协调与策略修订。

**关键证据：** 作者在五类地点、20 台机器的设置中比较五个 LLM Agent 与规则库存控制基线；其中四个 Agent 未超过该基线。计入推理成本后，模型排名也会变化。

**学习启发：** 长程 Agent 评测应同时记录最终回报、决策成本、资源承诺和从反馈中修正策略的能力。

来源：[论文页面](https://huggingface.co/papers/2610.36980)。

### 5. Auriga：用执行监控缩小机器人规划—执行差距

**一句话解释：** Auriga 是任务无关的机器人 Agent harness，让模型负责决策，同时为执行提供测量、预演、约束检查和恢复反馈。

**比喻讲解：** 指挥员先确定抓取方案，量尺提供精确位置，预演确认路线，安全员在偏离时叫停并说明偏差。模型像指挥员，harness 则提供让计划能落到实体动作的整套辅助。

**核心方法：** 通过显式任务信念、校准三维测量、以手指为参照的双臂控制和统一准入接口执行；运动前检查可视化轨迹预览，执行中核验阶段容差与抓取边界。

**关键证据：** 作者报告在 RoboDojo 上成功率为 57.7%，并称其在同一模型下比参考 harness 高出一倍以上；在 RoboCasa365 上报告 73.2%。数字来自作者的零样本、冻结 harness 评测设置。

**学习启发：** 机器人 Agent 的工程重点不仅是规划模型，还包括可观测状态、动作前预演、执行中止条件与可恢复的误差信号。

来源：[论文页面](https://huggingface.co/papers/2611.01112)；[项目页面](https://auriga.stelledge.com/)；[官方代码](https://github.com/lose4578/Auriga)。

### 6. FlyHash：把 Agent 记忆检索的“准确”和“实用”分开看

**一句话解释：** 研究比较了受果蝇嗅觉启发的 FlyHash 在 Agent 记忆检索中的邻居保持能力，以及实际存储和延迟代价。

**比喻讲解：** 给档案编号时，编号相近不代表档案柜更省空间或取件更快。FlyHash 更像一种在相同编号长度下较会把相似文件排在一起的规则；但实际档案体积和翻找成本仍要与传统索引分别比较。

**核心方法：** 以稀疏随机投影和赢家通吃构造哈希码，在匹配位数、真实相关性标签与多数据集条件下，对比 FlyHash、SimHash 和 HNSW。

**关键证据：** 作者报告在相同位数下 FlyHash 的记忆检索 mAP 为 0.271、SimHash 为 0.105（k=32）；但其码更大、比较更慢，普通规模下 HNSW 优于两种哈希法。作者明确将其定位为质量/位数结果，而非通用替代品。

**学习启发：** 选记忆检索方案时，先区分硬存储预算、检索质量和端到端延迟；不能只凭一种压缩指标替换向量索引。

来源：[论文页面](https://huggingface.co/papers/2611.05791)；[项目页面](https://huggingface.co/spaces/pranamhan/flyhash-agent-memory-demo)。

## 开源项目精选

### 7. herdrdev/herdr：在同一终端管理多个 Agent 会话

**用途：** Herdr 是面向编码 Agent 的终端会话管理工具。

**比喻讲解：** 同时开着几个终端时，可以在一个列表里看到哪个任务仍在运行，哪个正在等你输入。断开客户端后，重新连接还能回到后台服务仍在运行的终端。

**值得关注的功能：** 支持终端分屏、SSH 会话和 Agent 状态显示。机器重启后可恢复布局，并恢复部分受支持的 Agent 会话。

**使用门槛：** 按平台选择可执行文件，远程使用需要 SSH 环境。仓库采用 Apache-2.0 许可证。

**建议：** 有多个终端任务并行运行时，可先查看会话恢复说明，了解断开客户端和重启机器时各自能恢复哪些状态。

来源：[官方仓库](https://github.com/herdrdev/herdr)。

### 8. zed-industries/zed：在编辑器内查看并修改 Agent 的代码改动

**用途：** Zed 是支持多人协作的代码编辑器，内置用于处理编码任务的 Agent Panel。

**比喻讲解：** 你可以把几个文件交给 Agent，然后留在编辑器内检查改了哪些地方，并继续手动调整。协作窗口与代码编辑区共享当前项目。

**值得关注的功能：** Agent Panel 支持在项目中发起任务、查看改动，也支持通过 ACP 接入兼容的外部 Agent。

**使用门槛：** 需要安装对应平台的 Zed。模型访问和外部 Agent 的配置要求以所选提供方的文档为准。

**建议：** 可以在一个小项目里对照内置 Agent 和已有编码工具的改动审阅流程，看看哪种方式更适合你的习惯。

来源：[官方仓库](https://github.com/zed-industries/zed)；[Agent Panel 文档](https://zed.dev/docs/ai/agent-panel)。
