## 研究精选

### 1. Axion 1.0：开放 Agent 基座模型的简化训练配方

**一句话解释：** Axion 1.0 用两阶段监督微调加一阶段强化学习，构建开放且可复现的 Agent 基座模型。

**比喻讲解：** 第一阶段让学生练独立推理，第二阶段让他拿工具处理可核对的现实问题，最后通过连续任务学习在长流程中行动；这分别对应两段 SFT 与一段 RL。

**核心方法：** 作者说明，先以“模型感知”的数据构造强化自包含推理，再构造依赖工具且可自动验证的任务，最后用 Agent 轨迹强化学习增强长程推理和工具交互。

**关键证据：** 作者页面称完整公开数据构建、筛选、验证、提示词与训练代码；作者报告 35B 复现检查点在 HLE、BioMysteryBench、SEAL-0、HiPhO、FrontierScience 等六项设置上给出分数。指标为作者报告，须依论文协议解读。

**学习启发：** 复现 Agent 训练时，除权重外还应记录任务生成、验证器和过滤规则；它们决定训练信号是否可重复。

来源：[论文页面](https://huggingface.co/papers/2611.03233)；[官方代码](https://github.com/bytedance/axion1_0)；[项目页面](https://axion1-0.github.io/)。

### 2. ToolSpace：由真实工具组合扩展长程任务环境

**一句话解释：** ToolSpace 从真实 MCP 服务和 Agent 语料的执行轨迹出发，先形成工具组合图，再合成状态、环境和可验证任务。

**比喻讲解：** 它不先凭空设计厨房和菜谱，而是观察真实厨师哪些工具常相连、哪一步改变库存；再从这些可靠连接中走出可回放路线，并翻译成考题。

**核心方法：** 系统以确定性规则挖掘相邻调用的数据、状态和重试依赖，聚类成加权工具组合图；对有状态环境合成数据库，对查询类工具回放记录返回，再用可回滚的状态感知随机游走生成并验证任务。

**关键证据：** 作者报告，升级后的 AutomationBench 与 τ³-Bench Banking Pro 令 7 个前沿模型最多下降 38.2 分；在七个长程工具基准上，Qwen3.6-35B-A3B 平均分由 23.0 到 41.0（RL 后 43.2）。结果受环境、模型版本与评测设置限制。

**学习启发：** 为工具 Agent 造数据时，可优先保存真实执行边和可重放状态，而不只依赖模型虚构接口与任务。

来源：[论文页面](https://huggingface.co/papers/2611.05036)；[官方代码](https://github.com/dongguanting/ToolSpace)；[项目页面](https://toolspace-agent.github.io/)。

### 3. WebHarbor：可重置的真实网站式 GUI Agent 训练场

**一句话解释：** WebHarbor 将真实服务的界面、内容和工作流做成 153 个可执行、容器化环境，供 GUI Agent 评测和 RL 训练。

**比喻讲解：** 真实网站像每天改路、可能封路的城市；WebHarbor 是能恢复原状的训练城。Agent 可练习登录、预订和交易，考官也能可靠检查最后状态。

**核心方法：** 项目通过人机协作按任务扩展环境：编码 Agent 实现功能，人类审核视觉、功能和任务有效性；环境提供确定性控制、快速重置以及对最终回答和状态变化的验证。

**关键证据：** 作者报告套件含 153 个环境和 3,518 个多步、登录后工作流任务；只在 WebHarbor 做 RL 的 4B 级 GUI Agent，在 WebVoyager 与 Online-Mind2Web 平均 75.8，比其报告的 live-web 训练 OpenWebRL-4B 高 5.2 分。须按训练排除集与基准设置理解。

**学习启发：** GUI Agent 比较应区分“临时可访问的真实网页”与“稳定、可验证的训练环境”；后者更适合迭代训练。

来源：[论文页面](https://huggingface.co/papers/2611.03634)；[官方代码](https://github.com/aiming-lab/WebHarbor)；[项目页面](https://aiming-lab.github.io/WebHarbor/)。

## 开源项目精选

### 4. vercel-labs/agent-desktop：基于无障碍树的桌面自动化 CLI

**用途：** 让 Agent 在 macOS、Windows 与 Linux 上通过操作系统无障碍树读取和操作桌面应用，适合需要结构化桌面交互的场景。

**比喻讲解：** 截图只像一张照片；无障碍树是建筑蓝图，明确元素是按钮、文本框或列表项。Agent 按引用操作，再重新读取结构确认结果。

**值得关注的功能：** 官方说明其不依赖像素匹配或内置模型；CLI 返回带元素引用的 JSON，可点击、输入并再次快照验证，也提供 C 库。

**使用门槛：** 需要系统无障碍权限和对应平台环境；快照、剪贴板、截图、命令输出或调试材料可能含私人桌面信息，官方提示不要上传公共日志。许可证为 Apache-2.0。

**建议：** 适合评估桌面 Agent 的可观察性与操作闭环；接入前先确认权限模型、敏感数据边界和每次操作后的验证机制。

来源：[官方仓库](https://github.com/vercel-labs/agent-desktop)。

### 5. vercel-labs/agent-browser：面向 Agent 的浏览器自动化 CLI

**用途：** 让 Agent 用命令行打开页面、读取无障碍结构、按元素引用操作并复查结果，适合可审计的浏览器任务流。

**比喻讲解：** 像给网页按钮和输入框贴临时编号；Agent 先读编号清单，做一步操作，再重新贴编号确认变化，而不凭记忆盲点下一步。

**值得关注的功能：** 原生 Rust CLI 的 `snapshot` 输出紧凑文本和元素引用；浏览器会话可持续，支持语义定位、截图、下载、网络状态和 CDP 连接。

**使用门槛：** 首次使用需安装 CLI 和浏览器运行时；页面导航或 DOM 变动后旧引用失效，需要重新快照。许可证为 Apache-2.0。

**建议：** 值得关注其“观察—操作—再观察”范式；生产任务仍应为登录、支付和敏感提交设置明确授权与人工复核。

来源：[官方仓库](https://github.com/vercel-labs/agent-browser)。
