## 研究精选

### 1. Resolution Hypothesis：先能看清改进，再积累改进

**一句话解释：** 论文提出，Agent 进化可能并非缺少更好的候选，而是评测噪声使选择器无法可靠识别它们。

**比喻讲解：** 两个零件重量只差一点，而秤的读数每次波动更大；即使更轻的零件确实存在，按一次读数挑选也可能选错。多轮挑选后，错误会累积。

**核心方法：** 在候选选择和方法排名两个层面研究评估噪声，比较多种 Agent 进化方法与模型的独立运行结果。

**关键证据：** 作者研究七种方法、六个模型，报告候选选择区分有效和有害改动的能力不优于随机；方法间几个百分点的差异也可能小于同一方法独立运行的波动。

**学习启发：** 比较技能、提示或记忆优化方案时，应重复运行并报告不确定性，而不只看单次排行榜。

来源：[论文页面](https://huggingface.co/papers/2611.23068)。

### 2. Piccolo：决策模型和训练数据共同改进

**一句话解释：** Piccolo 是覆盖 0.8B 至 27B 的多模态决策模型系列，使用研究 Agent 迭代数据与训练方案。

**比喻讲解：** 教练观察学生在哪类题目上出错，调整训练题库，再根据考试结果修订下一轮训练。模型、题库和实验记录一起演化。

**核心方法：** 研究 Agent 分析行为、构造数据、开展实验，并通过语义切片和共享研究记忆连接多轮工作。

**关键证据：** 作者报告 Piccolo-27B 在 Decision Index Vision Full 上得分 75.59；论文还指出训练损失持续降低不一定带来离散决策准确率提升。该结果依其评测设置。

**学习启发：** 决策模型的训练应同时监测目标任务准确率、数据选择与模型骨干之间的相互作用。

来源：[论文页面](https://huggingface.co/papers/2611.24651)；[项目页面](https://decisionplayground.agentscope.io/)。

### 3. StatePortal：给深层 GUI 测试制作检查点

**一句话解释：** StatePortal 根据自然语言测试用例和只读源码，生成可重放的应用状态检查点。

**比喻讲解：** 测试员每次都从游戏第一关走到第十关很耗时；可复用存档让他直接回到第十关，但仍要检查存档里的状态和画面是否都正确。

**核心方法：** 为应用绑定或合成状态恢复 hook，并结合程序状态与视觉 oracle 验收检查点；DeepStateBench 包含 10 个应用的 61 项深状态任务。

**关键证据：** 作者报告，在相同像素动作空间中，使用合成检查点的 GUI Agent 完成 10.4% 的试验，无检查点为 0%；StatePortal 通过 hook 也完成目标动作时为 27.5%。

**学习启发：** 测试交互软件时，可把到达状态的成本与完成目标动作分开计量，同时检查状态和渲染。

来源：[论文页面](https://huggingface.co/papers/2611.23257)；[官方代码](https://github.com/pzy2000/State_Portal)。

### 4. PIPETTE：让攻防训练覆盖更多注入方式

**一句话解释：** PIPETTE 将提示注入红队发现转化为针对 Agent 的对抗训练，并鼓励攻击策略多样性。

**比喻讲解：** 如果消防演习永远模拟同一种火情，处理那一种场景的成绩会越来越好，但遇到不同火情仍可能失效。框架鼓励发现不同策略，再用它们训练防守方。

**核心方法：** 使用基于字典学习的奖励扩展攻击策略覆盖，并结合针对间接提示注入的在策略对抗训练。

**关键证据：** 作者在 AgentDojo 和 ASB 上报告，训练后的防守方在其静态攻击测试中攻击成功率接近零，并能抵抗测试中的自适应攻击，同时接近原有正常任务表现；不代表对所有攻击有效。

**学习启发：** 安全评估不应只追求红队攻击成功率，也要检查攻击多样性及防御后的正常任务效果。

来源：[论文页面](https://huggingface.co/papers/2611.24362)。

## 开源项目精选

### 5. vishalbanwari26/agent-diff：上线前比较 Agent 的行为变化

**用途：** Agent-diff 回放历史会话，比较当前版本和候选版本的回答及工具动作，帮助人工审核变更。

**比喻讲解：** 两位员工接到相同模拟工单，审核员并排查看他们的回答和准备采取的动作。模拟中的写入动作不真的执行，新增动作会交给人复核。

**值得关注的功能：** README 描述了会话回放、只读查询、变化判定和人工审批；未记录过的写入动作被标记为需要关注。

**使用门槛：** 项目使用 Node 工作进程、队列及模型评判；接入真实会话前需处理敏感数据、重放权限和外部模型服务配置。

**建议：** 可先用虚构数据测试重放和误报，再决定哪些真实行为适合纳入发布门槛。

来源：[官方仓库](https://github.com/vishalbanwari26/agent-diff)。
