## 研究精选

### 1. StreamDuo：让实时解说 Agent 按需询问研究 Agent

**一句话解释：** 面对未见游戏，解说模型按需向另一个 Agent 查询游戏 Wiki，并继续处理直播流。

**比喻讲解：** 解说员熟悉比赛节奏，却不认识角色和道具；后台助手专门翻资料。系统学习什么时候值得打断去问，以及怎样把可能带噪的答案融入解说。

**核心方法：** 以可训练解说器配合冻结研究 Agent，用信息增益标签学习提问时机，再以自蒸馏学习使用含噪回答。

**关键证据：** 作者摘要报告，在《博德之门 3》训练、十款未见游戏测试时，相对同数据训练的 Proact-VL，实体召回从 0.082 提升至 0.116，源游戏知识泄漏从 9.9% 降至 1.0%；结论限于该跨游戏解说设置。

**学习启发：** RAG / Agent 设计可把“是否值得检索”和“检索期间主流程如何继续”作为独立问题。

来源：[论文页面](https://huggingface.co/papers/2611.01120)；[官方代码](https://github.com/ZixianGao/StreamDuo-code)。

### 2. FrontierPhysics：评测 Agent 的完整科研流程

**一句话解释：** 用接近真实科研的任务，观察 Agent 能否从查文献做到研究结果与稿件产出。

**比喻讲解：** 把 Agent 当作待考核科研助理：先找资料、设计方案、做实验，再交有证据支持的报告；评委同时检查过程正确性与研究质量。

**核心方法：** 42 位物理学家构建 56 个任务、覆盖九个领域，结合确定性验证器和专家评分标准。

**关键证据：** 摘要报告测试 22 个模型、26 种配置；每种配置的 168 次 rollout 中，通过次数均未超过 46 次。该数字是单一配置运行次数，不能等同于完成 46 个任务。

**学习启发：** Agent 评测可同时验证引用、计划、实验与最终结论，而不是只看最终回答。

来源：[论文页面](https://huggingface.co/papers/2611.06910)。

### 3. PyRUA-DataFarm：用编程 Agent 生成机器人训练数据

**一句话解释：** 编程 Agent 在仿真中重建任务并生成带动作标注的数据，减少逐条人工遥操作采集。

**比喻讲解：** 这像一间虚拟教学录像工厂：参考一次真实示范搭好练习场，编排动作、拍多个视角，再由独立质检员审核后入库。

**核心方法：** 根据数据需求和一次场景标定示范，由 Agent 编写场景、专家控制器和成功判定器；仿真产生动作，视频模型生成多视角画面。

**关键证据：** 作者摘要报告，在五项真实机器人任务中，生成数据训练策略与遥操作数据训练策略在 100 次试验中分别成功 93 次和 84 次；需结合正文的数据规模与任务设置理解。

**学习启发：** 可借鉴“生成—独立审核—入库”的数据流水线，尤其避免生成器兼任审核者。

来源：[论文页面](https://huggingface.co/papers/2611.05320)；[项目代码分支](https://github.com/DAGroup-PKU/PyRUA-Lean/tree/DataFarm)。

### 4. What Does Multi-Turn Reinforcement Learning Really Improve in LLM Agents?：多轮强化学习的收益受预算约束

**一句话解释：** 该研究考察多轮 Agent 强化学习在不同采样宽度与交互深度下的表现，指出它主要提升纠错与长程稳健性，而非普遍提高单步决策。

**比喻讲解：** 把 Agent 看成办事助理：多轮训练更像教它在流程走偏后回头修正，而不是让每一步都天然更聪明。若只给很少的来回机会，再会补救也发挥不出来。

**核心方法：** 作者以 Pass@(K,T) 同时考察采样宽度 K 与交互深度 T，并提出训练时混合不同交互预算的 BudgetMix RL。

**关键证据：** 作者摘要称，轨迹级强化学习的优势在回合预算收紧时显著减弱；BudgetMix RL 在多种执行设置下呈现更稳健表现。该结论来自摘要，未在本次任务中复现实验。

**学习启发：** 评估 Agent 时应把最大工具调用或交互轮数写入评测条件；训练与部署预算不匹配时，离线优势未必能迁移。

来源：[论文页面](https://huggingface.co/papers/2611.06483)；[项目页面](https://rethinking-agentic-rl.github.io/)。

## 开源项目精选

### 5. NVIDIA/auto-ontology：为数据分析 Agent 提供业务语义

**用途：** 从企业元数据建立语义和图结构，解释指标、实体、关系与数据来源，供 Agent 检索上下文和查询数据库。

**比喻讲解：** 新员工面对满柜缩写文件，即使找得到也未必理解“收入”的口径。它像资料管理员，把术语、关系和出处整理成词典与地图。

**值得关注的功能：** 官方说明包含元数据发现、业务定义对齐、查询校验、来源追踪，并提供 MCP、CLI 和 API 接口。

**使用门槛：** 项目含数据库、后端和前端组件；快速开始需要 Docker Compose、uv 与 NVIDIA API Key，许可证为 Apache-2.0。

**建议：** 适合先阅读其如何组织业务定义与来源，再判断是否符合自己的 RAG、知识图谱或 Text-to-SQL 场景。

来源：[官方仓库](https://github.com/NVIDIA/auto-ontology)。

### 6. max-sixty/worktrunk：管理多个编程 Agent 的 Git worktree

**用途：** 简化 worktree 的创建、切换、列表和清理，让并行任务有各自独立的工作目录。

**比喻讲解：** 多位程序员若挤在同一工作台，容易碰到彼此正在改的材料。Worktree 提供独立工作台，Worktrunk 像管理员，负责分配、切换与收拾。

**值得关注的功能：** 除目录管理外，提供 hooks、合并辅助和状态查看；隔离目录不等于自动解决最终合并冲突。

**使用门槛：** 需要理解 Git 分支和 worktree；Windows 下命令名可能与 Windows Terminal 的 `wt` 冲突，可使用 `git-wt`。

**建议：** 适合多任务并行的编码工作流；可先在练习仓库创建两个 worktree 熟悉隔离和合并过程。

来源：[官方仓库](https://github.com/max-sixty/worktrunk)。

### 7. thedotmack/claude-mem：跨会话的 Agent 记忆层

**用途：** 为 Claude Code、Codex 等多种 Agent 捕获会话中产生的上下文，压缩并在后续会话中注入相关信息。

**比喻讲解：** 长期项目换班时，新同事通常需要翻聊天记录。它相当于一名记录员，把过程整理成可检索的交接摘要，让下一位助手不必从头回放全部对话。

**值得关注的功能：** 官方仓库将其定位为跨会话持久上下文，列出多个 Agent / 编码工具的适配，并提供多种插件目录。

**使用门槛：** 需要审阅其收集与存储的会话内容；会话快照、剪贴板或调试信息可能含私人数据，使用前应核对数据边界。许可证为 Apache-2.0。

**建议：** 对长上下文、代码 Agent 记忆或跨工具工作流感兴趣时，优先查看它的上下文压缩和注入策略，并先在非敏感项目验证。

来源：[官方仓库](https://github.com/thedotmack/claude-mem)。
