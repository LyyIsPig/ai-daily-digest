## 研究精选

### 1. AutoMaster：改善教师给出的示范

**一句话解释：** AutoMaster 分析 Agent 轨迹，设计自然语言技能提示，让同一个教师模型生成更有用的训练示范。

**比喻讲解：** 学生模仿老师做题时，即使老师最终答对，中间也可能有反复试错或未经核对的猜测。AutoMaster 像一位教练，先查看录像找出不良习惯，再提醒老师怎样示范，最后用新的示范录像训练学生。

**核心方法：** 系统通过轨迹分析、技能设计、数据选择和反馈迭代，先引导教师生成轨迹，再用这些轨迹做监督微调。

**关键证据：** 作者摘要报告，在 Terminal、Search 和软件工程任务中，4B、9B 目标模型相对使用成功但未引导轨迹的普通 SFT 平均提升 1.42–8.99 个百分点；教师、任务池、训练集规模和 SFT 配方保持一致。论文于 11 月 19 日发布，11 月 20 日提交至 HF 日榜。

**学习启发：** 构建 Agent 训练数据时，除了筛选最终成功的轨迹，也可检查中间行为是否值得模仿。

来源：[论文页面](https://huggingface.co/papers/2611.26510)。

### 2. CompoundingKernel：让多 Agent 累积 GPU 优化成果

**一句话解释：** 该系统从 PyTorch 定义出发，组织多个 Agent 搜索 GPU kernel，并保存通过外部检查的方案。

**比喻讲解：** 多位厨师各自改良同一道菜，品鉴员先检查是否符合要求，再把合格菜谱和改动关系放进档案。负责人查看档案后，给不同厨师分配下一轮改良方向。

**核心方法：** 每个问题有独立的正确 kernel 档案；LLM 控制器选择已有方案或新设计，让并行子 Agent 尝试，模型外部的检查器判断正确性。

**关键证据：** 摘要报告，截至 11 月 11 日，SOL-ExecBench 的 NVIDIA B200 设置下，235 个问题都有经网站验证正确的 kernel；209 个公开榜单问题相对基准参考实现达到 4.40 倍速度。该数字是特定硬件和基准下作者报告的结果。论文于 11 月 14 日发布，11 月 20 日提交至 HF 日榜。

**学习启发：** 复杂搜索可将候选方案、谱系和独立验证结果持久化，让下一轮尝试复用可靠成果。

来源：[论文页面](https://huggingface.co/papers/2611.19230)；[作者项目页面](https://huggingface.co/spaces/QianQu/CompoundingKernel-Explorer)。

## 开源项目精选

### 3. mahdi-al-hakim/warden：为 Agent 操作设置审批关口

**用途：** Warden 演示如何在 IT 员工离职流程中审核 Claude Agent 提议的工具调用。

**比喻讲解：** Agent 像填写操作申请的工作人员，策略代理像门卫：检查目标和规则，对需要人工决定的步骤暂缓，并记录放行或拒绝的理由。

**值得关注的功能：** README 描述了作用范围限制、人工审批、撤销检查、哈希链审计记录和执行后的系统状态回读；作者也提供提示注入实验和控制措施测试。

**使用门槛：** 默认离线回放无需密钥，实时模式需要 Claude API；除可选测试 GitHub 组织外，系统使用模拟数据。MIT 许可证。作者明确指出生产使用还需持久化、身份认证和真实连接器。

**建议：** 适合研究工具调用的策略执行和可审计设计；演示结果不能直接视为生产系统的安全保证。

来源：[官方仓库](https://github.com/mahdi-al-hakim/warden)。

### 4. marcus-beauregard/agent-runner：搭建可检查的编程 Agent 循环

**用途：** 这是一个早期 Go 项目，探索围绕代码仓库任务组织规划、执行与运行记录。

**比喻讲解：** 项目像一条尚在组装的流水线：传送带和工具登记处已经搭好，但负责决策的工人目前还是模拟角色，不能据此认为整条自动生产线已完工。

**值得关注的功能：** README 列出计划、行动、观察、反思循环，以及工具注册表、策略和命令执行组件。项目明确说明 worker 大部分尚未实现，当前规划器是确定性模拟，不调用模型。

**使用门槛：** 需要 Go 编译环境；默认示例可离线运行。许可证 GPL-2.0-or-later。官方提示项目处于早期，不要指向他人的仓库。

**建议：** 适合阅读一个小型 Agent 框架的模块拆分，不宜把现阶段的计划描述当成已实现功能。

来源：[官方仓库](https://github.com/marcus-beauregard/agent-runner)。

### 5. shuymn/stack：整理编程 Agent 的会话与合并

**用途：** stack 是 Go 命令行工具，面向 Claude Code、Codex 等个人编程 Agent 工作流。

**比喻讲解：** 多人轮流工作时，交接簿保存当前任务状态，验收门在材料送出前核对版本和检查结果。stack 的会话交接与合并命令分别承担类似角色。

**值得关注的功能：** 官方说明包含会话 kit、Claude 会话钩子、按指定 head SHA 和检查结果控制的合并，以及通过 JSON 接口运行的可选扩展。

**使用门槛：** 需要 Go 和对应 Agent 工具；部分检查由单独扩展提供，需要正确安装配置。README 还说明版本迁移期间应核对保护规则是否实际生效。

**建议：** 对编程 Agent 的交接和合并治理感兴趣时，可先阅读架构和扩展边界，再在测试仓库中验证配置。

来源：[官方仓库](https://github.com/shuymn/stack)。
