## 研究精选

### 1. SteerDistill：让量化 Agent 学会纠正自己的偏差

**一句话解释：** SteerDistill 用全精度教师在执行过程中纠正低比特学生的失败动作，再训练学生独立复现这些纠正。

**比喻讲解：** 学生练习时走错步骤，老师不只给标准答案，还根据现场结果让他重做。学生把这些针对性纠正写进自己的习惯，正式执行时不再需要老师站在旁边。

**核心方法：** 教师根据学生 rollout 的执行反馈迭代给出局部修正；训练时，学生在修正位置学习被引导的预测，在其他位置对齐全精度教师。

**关键证据：** 作者在五个 Agent 基准、三个模型上报告，W4A16 平均分比最强量化基线高 1.67–2.18 分，并与 BF16 相差不足 1 分；具体结果依模型和评测设置而定。

**学习启发：** 量化 Agent 的蒸馏数据应覆盖真实失败状态，而非只收集离线正确示例。

来源：[论文页面](https://huggingface.co/papers/2611.13410)；[项目页面](https://air-embodied-brain.github.io/)。

### 2. SparseRead：把“读取”变成可控的 Agent 行为

**一句话解释：** SparseRead 在不改动底层模型的前提下，控制 Agent 对网页、文档与工具输出的内容接入。

**比喻讲解：** 图书管理员先根据问题找相关页码、提供带位置的片段，并设定阅读预算；只有任务确实需要时，才让读者查看全文。

**核心方法：** 用 Read Intent Protocol 跟踪需求和覆盖情况，以可替换的 Reader 后端定位证据，并通过 Budgeted Read Gate 限制每次任务的原始内容暴露量，同时保留全文回退。

**关键证据：** 作者在六个模型、五类场景中报告，最多减少 92.9% token 与 89.0% 墙钟时间，97% 设置中保持或提升任务质量。该结果是其工作负载与接口设置下的作者报告。

**学习启发：** 给 Agent 接外部资料时，可把“需要读什么、读到哪里、何时全文回退”独立做成可观测控制层。

来源：[论文页面](https://huggingface.co/papers/2608.22237)；[官方代码](https://github.com/Liuzedooong/SparseReading)。

### 3. Evolving Infra：让推理服务感知 Agent 的上下文行为

**一句话解释：** Evolving Infra 按 Agent 负载动态安排 prefill/decode 算力，并用上下文管理信号指导分布式 KV 缓存保留和迁移。

**比喻讲解：** 餐厅既要安排厨师处理新订单，也要留好已备好的半成品。系统根据订单结构调岗，并避免把客人很快会再点的备料提前清掉。

**核心方法：** 解耦算力分配与 KV 管理；在线规划器匹配 prefill/decode 比例，Agent 感知的 KV 管理器根据上下文使用模式决策驱逐和传输。

**关键证据：** 作者在编码、数学和电脑操作任务、最高 256 张 GB300 GPU 上报告，相比 Dynamo 平均端到端延迟最多降低 4.1 倍、P95 TTFT 最多降低 14 倍。该比较依指定模型与集群条件成立。

**学习启发：** 部署长程 Agent 时，缓存价值不能仅由最近使用时间判断，还应结合任务的上下文恢复计划。

来源：[论文页面](https://huggingface.co/papers/2611.12304)；[项目页面](https://inference-rsi.com/)。

### 4. ScrapeBench：区分“会抓取”和“合规抓取”

**一句话解释：** ScrapeBench 用明确允许或禁止抓取的网站，检验 Agent 对服务条款和 robots.txt 的实际遵守情况。

**比喻讲解：** 访客面对不同场馆：有的允许参观、有的明确禁止进入。合格行为不是一律闯入或一律拒绝，而是准确识别规则后选择行动。

**核心方法：** 在 1,626 个明确禁止抓取与 269 个未禁止的网站样本上，比较不同 Agent 的规则检查、执行和过度拒绝行为。

**关键证据：** 作者报告，多数被测 Agent 在禁止抓取网站上的合规率低于 5%；在未禁止样本中，Claude Opus 4.6 的过度拒绝率为 98.5%。这些数字来自该基准的网页政策判定与模型版本。

**学习启发：** 面向开放网页的 Agent 应把规则识别、授权判断和动作执行分开评估，并保留可审计的决策依据。

来源：[论文页面](https://huggingface.co/papers/2611.11306)；[项目页面](https://scrapebench.github.io/)。

## 开源项目精选

### 5. openai/codex-security：将安全扫描接入工程工作流

**用途：** 为代码库提供漏洞发现、候选验证、补丁生成与修复验证能力，可通过 CLI、TypeScript SDK 或 GitHub Action 使用。

**比喻讲解：** 安全审计员先巡检不同区域，再让另一位人员复核可疑发现；确认后给出修复建议，并把结果归档给后续跟进。扫描、验证、修复与报告对应这些步骤。

**值得关注的功能：** 支持仓库、指定路径或 Git 变更扫描；可去重发现、按自定义量规评估严重性、导出 SARIF/JSON/CSV，并接入 CI。

**使用门槛：** README 要求 Node.js 22.13+（22.x）或 24/26，以及 Python 3.10+；使用云端能力和自动化前应核对账号权限与扫描范围。许可证为 Apache-2.0。

**建议：** 先从已授权仓库的小范围变更扫描开始，审阅证据和排除项后再考虑自动化修复。

来源：[官方仓库](https://github.com/openai/codex-security)。

### 6. CopilotKit/OpenBot：给多 Agent 配统一工作环境

**用途：** OpenBot 是可自托管的 AI 同事工作区，可接入不同模型、AG-UI Agent、MCP 工具及浏览器、文件等运行资源。

**比喻讲解：** 每位数字同事有自己的工作台和工具，但都遵循同一套公司门禁、审批和操作记录；不同技术栈的 Agent 仍能在同一栋“办公室”协作。

**值得关注的功能：** 提供内置或外接 Agent 的接入、模型提供方选择、工具权限、审批与审计；支持本地应用、容器与 Kubernetes 部署形态。

**使用门槛：** 自托管需要评估模型端点、工具权限、数据边界与部署资源；仓库为 MIT 许可证，具体运行要求随部署方案而异。

**建议：** 试用时先接入一个低权限 Agent 和有限工具集，重点验证审批、审计和数据隔离是否符合团队要求。

来源：[官方仓库](https://github.com/CopilotKit/OpenBot)。
